📋 项目简介
 
这是一个专为复旦FM1280 JavaCard设计的FM1208 CPU卡电子钱包模拟器，用于PBOC离线余额系统的安全测试与防护研究。本项目通过精确模拟FM1208的指令集、文件系统和交易流程，帮助开发者和安全研究人员发现并修复离线电子钱包系统中的安全漏洞，从而加强余额保护机制。
 
国内绝大多数离线余额系统（如校园卡、门禁卡、消费卡，某些水卡系统等）均基于复旦FM1208芯片或兼容的CPU卡电子钱包实现，本项目可在任何支持JavaCard 2.2.2的智能卡上运行，实现与合法卡片完全一致的交互行为。
 
🎯 项目目的
 
- 安全研究：深入分析PBOC离线电子钱包的安全机制和潜在漏洞
- 系统测试：验证离线余额系统的防护能力，特别是针对重放攻击的防御措施
- 防护加强：为开发者提供参考，帮助设计更安全的离线支付系统
- 教学演示：用于智能卡安全和支付系统的教学与培训
 
✨ 核心特性
 
- 跨平台支持：可在复旦FM1280、JCOP、NXP J3A等所有支持JavaCard 2.2.2的智能卡上运行
- 完整文件系统：实现了FM1208标准的MF/DF/EF三级文件结构
- 真实交易流程：支持充值、消费、余额查询、交易记录查询等完整功能
- 原子交易保护：使用JavaCard事务机制确保余额更新和交易记录的原子性
- 轻量级设计：代码精简，内存占用低，适合资源受限的智能卡环境
 
🔧 工作原理
 
本项目基于重放攻击原理实现，针对以下类型的离线余额系统可实现与合法卡片完全一致的功能：
 
- ✅ 不联网的纯离线交易系统
- ✅ 无PSAM卡保护或PSAM卡密钥泄露的系统
- ✅ 不验证MAC1（终端不验证卡片返回的MAC）的系统
- ✅ 无外部认证或PIN验证的系统
- ✅ 仅检查交易指令格式和响应状态码的系统
 
技术实现细节：
 
- 使用固定ATC（应用交易计数器）绕过交易计数验证
- 使用固定MAC和固定随机数绕过消息认证码验证
- 精确模拟所有FM1208私有指令和标准PBOC指令
- 实现了完整的交易上下文管理和状态机
 
重要说明：如果您拥有系统的MAC密钥，可以轻松修改本代码实现动态MAC计算，使其成为完全合法的卡片。这也正是本项目的警示意义所在——离线系统的安全性完全依赖于密钥的保密性。

⚠️ 已知限制与安全风险
 
1. 测试版本限制：本版本使用固定MAC和固定ATC，仅用于测试目的，不具备真实的安全防护能力
2. 认证绕过：PIN验证和外部认证指令直接返回成功，未实现实际验证逻辑
3. 时间固定：交易日期时间使用固定值，未实现实时时钟功能
4. 密钥依赖：对于验证MAC1的系统，需要获取系统的MAC密钥才能正常工作
5. 联网系统无效：对于联网验证的系统，本项目无法绕过服务器端的余额检查
 
🧪 测试建议
 
1. 功能测试：使用pyApduTool或pcsc-tools发送标准APDU指令验证基本功能
2. 兼容性测试：在不同品牌和型号的支付终端上测试兼容性
3. 安全测试：测试系统对重放攻击、伪造交易、异常指令的防御能力
4. 压力测试：连续执行多次交易，验证余额计算的准确性和稳定性
5. 对比测试：与真实的FM1208卡片进行对比测试，验证行为一致性
 
🛡️ 安全防护建议
 
基于本项目的研究结果，建议离线余额系统采取以下防护措施：
 
1. 启用MAC1验证：终端必须验证卡片返回的MAC，防止重放攻击
2. 使用动态ATC：每次交易递增ATC，并在终端和后台进行验证
3. 实现双向认证：使用外部认证和内部认证确保卡片和终端的合法性
4. 定期联网同步：定期将交易记录上传到服务器进行对账
5. 使用PSAM卡：在终端中使用PSAM卡进行密钥管理和MAC计算
6. 加密交易数据：对敏感的交易数据进行加密传输
