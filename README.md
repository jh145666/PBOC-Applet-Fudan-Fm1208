# PBOC-Applet-Fudan-Fm1208

复旦微 FM1208 JavaCOS 卡的 **PBOC 借记/贷记电子钱包**完整实现：卡内 Applet + Android 工具箱 APP + 本地测试环境三件套。

⚠️ 本项目仅用于合法的安全研究、系统测试和学术交流，严禁用于任何非法用途。使用本项目即表示您同意仅在获得明确授权的范围内使用，并承担由此产生的一切法律责任。

## 📋 项目简介

本项目专为复旦 FM1208（FM1280 JavaCard）设计，实现 PBOC 电子钱包/电子存折的核心指令集与 FMCOS 2.0 完整文件系统，用于离线余额系统的测试与防护研究。项目包含三部分：

- 卡内：`FmcosWalletApplet`（Java Card 2.2.1 / FM1208 老卡兼容，v2.3）
- 手机：`JavaCOS-PBOC工具箱`（NFC 直连，内置 PBOC 收单、钱包、文件系统、Applet 设置与 GPDroid 卡管理）
- 测试：`applet-test-env`（无需真卡，Java 实现的 JavaCard API 桩回归测试）

国内大多数离线余额系统（校园卡、门禁卡、消费卡等）基于复旦 FM1208 芯片或兼容的 CPU 卡电子钱包实现。本项目可在任何支持 JavaCard 2.2.x 的智能卡上运行，实现与合法卡片一致的交互行为。

## ✨ 核心特性

- 跨平台支持：复旦 FM1280、JCOP、NXP J3A 等所有支持 JavaCard 2.2.x 的智能卡
- 完整文件系统：FMCOS 标准的 MF/DF/EF 三级文件结构，含 SFI 短文件标识
- 真实交易流程：圈存、消费、余额查询、交易记录查询完整实现
- 动态安全机制：动态 ATC（应用交易计数器）+ 真实 DES/3DES 过程密钥派生与 MAC/TAC 计算
- 原子交易保护：JavaCard 事务机制确保余额更新与交易记录的原子性
- 动态建文件：支持 80E0 建立/80E4 删除动态文件（二进制/定长记录/循环记录/DF）
- 一体化手机管理：APK 内置 GPDroid，可直接通过手机 NFC 安装/卸载/管理 applet，无需电脑
- 轻量级设计：代码精简，内存占用低，适合资源受限的智能卡环境

## 🚀 快速部署

### 环境要求

- 一张空白或已解锁的 JavaCard（推荐复旦 FM1280 且已关闭 M1 部分，即 SAK=20）
- 支持 PC/SC 的读卡器（ACR122U、PCR532、Proxmark3 等）或支持读写 ISO14443 CPU 卡的 Android 手机（NFC）
- Android 7+ 手机用于 APP 联调

### 安装 Applet（release/toolkit.cap）

CAP 文件位于 `release/toolkit.cap`，三种安装方式：

**① 手机版（推荐，用本 APK）**

无需电脑和读卡器。安装 `JavaCOS-PBOC工具箱` 后进入 **GPDroid** 页面，贴卡连接后点「**安装Applet**」选择 `toolkit.cap` 即可；也可在 GPDroid 中「列出Applet」「设为默认」「删除所有Applet」完成后续管理。首次连接若提示输入密钥集，使用卡的 GP 出厂默认密钥（见「默认密钥与参数」）。

注意：普通手机的 NFC 通常只支持卡模拟或标签读取，只有支持读写 ISO14443 CPU 卡的手机才能使用此方式，请先确认手机硬件支持。

**② 电脑版（PC + 读卡器）**

使用 GlobalPlatformPro（gp.jar）命令行安装，需作为默认选中的 applet：

```bash
java -jar gp.jar --install release/toolkit.cap --default
```

**③ 商家代装**

将 CAP 文件交给商家/写卡工具直接安装。

### 编译 Applet（可选）

- 推荐使用 JCIDE 打开根目录 `FmcosWalletApplet.java` 编译生成 CAP
- 备选：JavaCard SDK 2.2.2 命令行编译

### 安装 Android 工具箱（release/*.apk）

`release/JavaCOS-PBOC工具箱-v1.4.7.apk` 直接安装到 Android 7+ 手机（需 NFC）。打开后共五个页面：

| 页面 | 功能 |
|---|---|
| 主页（PBOC） | 贴卡自动走 PBOC 收单流程：应用选择 → GPO → 读记录 → 脱机数据认证 → 终端风险管理 |
| 钱包操作 | 选择应用 / 验证 PIN / 读余额 / 圈存 / 消费（含日志窗） |
| 文件系统 | 智能扫描 / 全量扫描 / 自定义扫描（FID 区间如 `2F00-2FFF`、逗号组合），扫描中可随时停止 |
| Applet 设置 | 发卡数据下发（80DC）、密钥下发、PIN 重写（自动解锁） |
| GPDroid | 安装/列出/删除/设为默认 Applet、密钥集与通道管理、安装参数、GET DATA、安装测试、APDU 回显 |

### 跑回归测试（无需真卡）

```bash
scripts/run_tests.sh

```

### 构建 APP（可选）

```bash
scripts/build_apk.sh
# 产物：tmp 工作目录下 toolbox-aligned-signed.apk（zipalign + v1/v2/v3 签名）
```

## 📁 文件系统结构

```
MF (3F00)
├── EF 0001  卡信息记录    定长记录 1×16   SFI=01（兼作 MF 目录）
├── EF 0005  卡序列号      二进制 16        SFI=05
└── DF 1001  电子钱包应用目录（AID = A0 00 00 00 03 86 98 07 01）
    ├── EF 0001  应用基本信息  定长记录 1×48  SFI=01
    ├── EF 0002  应用参数      定长记录 1×32  SFI=02
    ├── EF 0015  公钥信息      二进制 16      SFI=21
    ├── EF 0016  私钥信息      二进制 16      SFI=22
    └── EF 0018  交易记录      循环 10×23     SFI=24
```

动态文件：APP 可经 80E0 在 MF/DF 下建立最多 16 个动态文件（二进制/定长记录/循环记录/DF），总数据池 1536 字节，可用 80E4 删除。

## 📊 交易记录格式（EF 0018，每条 23 字节）

| 偏移 | 长度 | 说明 |
|---|---|---|
| 0 | 1 | 交易类型（01=圈存ED 02=圈存EP 05=消费ED 06=消费EP） |
| 1 | 2 | ATC（应用交易计数器） |
| 3 | 4 | 交易金额（大端序，单位：分） |
| 7 | 6 | 终端机编号 |
| 13 | 4 | 终端交易日期 |
| 17 | 3 | 终端交易时间 |
| 20 | 3 | 交易后余额（低 3 字节） |

## 🔐 安全机制说明

- 过程密钥派生：圈存使用 `DES(MK, 随机数4 + ATC2 + 0x80 00)`；消费使用 `DES(MK, 随机数4 + 脱机ATC2 + 终端序号最右2字节)`
- MAC 算法：PBOC CBC-MAC，数据 0x80 填充至 8 的倍数、零 IV，取最终块前 4 字节
- TAC：圈存/消费成功后以折半密钥（16 字节左右 8 字节异或）计算
- 交易成功后自动写入 0018 交易记录（可经 80DC tag 09 关闭）
- 默认不验证终端 MAC 与 PIN（80DC tag 05 可启用认证）

## ⚠️ 已知限制与安全风险

1. 默认配置为测试值：主密钥 `1E02313233343536`、PIN `123455`、双钱包各 30.00 元，均公开可查，不可用于真实发卡
2. 默认关闭认证：不验证终端 MAC 与 PIN，需通过 Applet 设置页/80DC tag 05 开启后才校验
3. 时间固定：交易日期时间由终端传入，卡内无实时时钟
4. 密钥依赖：终端若要验证 MAC1/TAC，需与卡片使用一致的密钥与派生算法
5. 联网系统无效：对于联网验证的系统，本项目无法绕过服务器端的余额检查
6. 动态文件受限于 1536 字节池，超出报 6A84
7. 手机 NFC 安装/管理 applet 依赖手机硬件支持读写 ISO14443 CPU 卡

## 🛡️ 安全防护建议

基于本项目的研究结果，建议离线余额系统采取以下防护措施：

1. 启用 MAC1 验证：终端必须验证卡片返回的 MAC，防止重放攻击
2. 使用动态 ATC：每次交易递增 ATC，并在终端和后台进行验证
3. 实现双向认证：使用外部认证和内部认证确保卡片和终端的合法性
4. 定期联网同步：定期将交易记录上传到服务器进行对账
5. 使用 PSAM 卡：在终端中使用 PSAM 卡进行密钥管理和 MAC 计算
6. 加密交易数据：对敏感的交易数据进行加密传输
